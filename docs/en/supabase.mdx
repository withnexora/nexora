# Supabase

`supabase-unified.sql` is the single canonical schema for the project. Run it once on a new project. For a production database with real orders, back up first and use a controlled migration.

## Public configuration

Copy `.env.example` to `.env`. The frontend uses `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`; backend/payment routes use `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY`. Only the publishable/anon key belongs in client code. Service-role keys, secret keys, and database credentials belong only in server/hosting environment variables. Do not edit `client/supabase-config.js` or put secrets in `VITE_*` variables.

## Storage

The `nexora-brand-assets` bucket stores images uploaded from Admin. Store only a URL/path in the database, never file bytes. See [Supabase Storage Setup](../SUPABASE_STORAGE_SETUP.md) for policies and URL verification.

## Verification

Verify Auth redirect URLs, RLS policies, owner-scoped RPCs, and webhook signatures before enabling production payments.
